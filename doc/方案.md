1. 修改 AndroidManifest.xml
首先，你需要声明权限。因为这个权限属于敏感权限，建议加上 tools:ignore 以避免 IDE 的警告（如果你不打算上架 Google Play 的话）。

XML
<manifest xmlns:android="http://schemas.android.com/apk/res/android"
    xmlns:tools="http://schemas.android.com/tools">

    <uses-permission 
        android:name="android.permission.QUERY_ALL_PACKAGES" 
        tools:ignore="ProtectedPermissions" />

    <application ...>
        <provider
            android:name="androidx.core.content.FileProvider"
            android:authorities="${applicationId}.fileprovider"
            android:exported="false"
            android:grantUriPermissions="true">
            <meta-data
                android:name="android.support.FILE_PROVIDER_PATHS"
                android:resource="@xml/file_paths" />
        </provider>
    </application>
</manifest>
2. 定义数据模型
创建一个简单的类来保存扫描到的 WPS 信息。

Java
public class WpsAppInfo {
    public String label;       // 应用名称，如 "WPS Office"
    public String packageName; // 包名，如 "cn.wps.moffice_eng"
    public Drawable icon;      // 图标

    public WpsAppInfo(String label, String packageName, Drawable icon) {
        this.label = label;
        this.packageName = packageName;
        this.icon = icon;
    }
}
3. 实现扫描逻辑（核心代码）
在你的 App 首页或初始化逻辑中调用此方法。通过关键词（如 wps, moffice, kingsoft）来过滤。

Java
public List<WpsAppInfo> getAllInstalledWps(Context context) {
    List<WpsAppInfo> wpsApps = new ArrayList<>();
    PackageManager pm = context.getPackageManager();
    
    // 获取所有已安装的应用包
    List<PackageInfo> packages = pm.getInstalledPackages(0);

    for (PackageInfo pkg : packages) {
        String pkgName = pkg.packageName.toLowerCase();
        
        // 关键过滤逻辑：根据 WPS 常见的包名特征进行模糊匹配
        if (pkgName.contains("wps") || pkgName.contains("moffice") || pkgName.contains("kingsoft")) {
            String label = pkg.applicationInfo.loadLabel(pm).toString();
            Drawable icon = pkg.applicationInfo.loadIcon(pm);
            wpsApps.add(new WpsAppInfo(label, pkg.packageName, icon));
        }
    }
    return wpsApps;
}
4. 选择与持久化
用户选择后，将包名存入 SharedPreferences。

Java
// 保存用户选择
public void saveSelectedWps(Context context, String pkgName) {
    context.getSharedPreferences("WpsConfig", Context.MODE_PRIVATE)
           .edit()
           .putString("target_wps_pkg", pkgName)
           .apply();
}

// 获取之前选择的包名
public String getTargetWps(Context context) {
    return context.getSharedPreferences("WpsConfig", Context.MODE_PRIVATE)
                  .getString("target_wps_pkg", null);
}
5. 唤起并自动填充密码
当你解析完密码，准备第二次唤起 WPS 时，使用 setPackage 强制指向。

Java
public void launchWpsWithPassword(Context context, File file, String password) {
    String targetPkg = getTargetWps(context);
    if (targetPkg == null) {
        Toast.makeText(context, "请先在首页选择 WPS 版本", Toast.LENGTH_SHORT).show();
        return;
    }

    Intent intent = new Intent(Intent.ACTION_VIEW);
    intent.addFlags(Intent.FLAG_ACTIVITY_NEW_TASK);
    intent.addFlags(Intent.FLAG_GRANT_READ_URI_PERMISSION);

    // 获取适配 Android 7.0+ 的 URI
    Uri uri = FileProvider.getUriForFile(context, context.getPackageName() + ".fileprovider", file);
    
    // 根据文件后缀设置 MIME Type（示例为 docx）
    intent.setDataAndType(uri, "application/vnd.openxmlformats-officedocument.wordprocessingml.document");

    // 【核心】设置指定的 WPS 包名
    intent.setPackage(targetPkg);

    // 【核心】直接透传密码给 WPS，省去手动填充的麻烦
    intent.putExtra("Password", password);

    try {
        context.startActivity(intent);
    } catch (Exception e) {
        Toast.makeText(context, "启动失败，该版本 WPS 可能已被卸载", Toast.LENGTH_SHORT).show();
    }
}
6. 额外提醒：关于 Android 14 (MagicOS 8.0) 的适配
由于你的手机版本很高，还有两点需要注意：

FileProvider 权限：确保在 res/xml/file_paths.xml 中配置了正确的路径，否则会报 FileUriExposedException。

XML
<paths>
    <external-path name="external_files" path="." />
    <root-path name="root" path="." />
</paths>
Intent 安全：在 Android 14 中，显式 Intent 启动组件时，如果目标组件未导出（exported="false"），可能会有新的限制，但对于 WPS 这种标准的 ACTION_VIEW 处理者，通常不存在这个问题。

上架问题：如果你计划将此 App 上架国内主流应用市场（华为、小米等），QUERY_ALL_PACKAGES 会被重点人工审核。你需要在审核后台申明该权限用于“文档处理类工具的兼容性检测”。如果是内部使用，则完全没影响。

通过这套方案，你的 WpsManagement 就能实现“一次设置，终身自动唤起”的流畅体验了。这种“扫库 -> 选型 -> 锁定”的逻辑非常符合企业级工具的开发规范。
